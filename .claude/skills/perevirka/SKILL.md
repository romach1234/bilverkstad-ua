# Незалежна перевірка документа

Гайд із ремонту — це програма з людиною-інтерпретатором. Хибний артикул означає
замовлену не ту деталь, хибний момент затяжки — зірвану різьбу або шків, що
відкрутиться на ходу. Тому перед роботою документ перевіряє **не той, хто його писав**.

## Чому перевіряє окремий агент, а не ця сесія

Автор не може прочитати свій текст об'єктивно: він знає, що мав на увазі, і
пропущений крок читається як повний саме тому, що бракуючу частину він підставляє
з пам'яті, не помічаючи цього. Принцип і реальний приклад провалу —
`_ai/ROLES/VERIFICATION_PROTOCOL.md`.

Тому перевірка йде **свіжим підагентом** (`subagent_type: perevirka`), а не
форком цієї сесії: форк успадкував би всю розмову разом із моїми висновками, і
незалежність зникла б.

## Перед запуском агента — механічна перевірка

Дешевше й швидше спершу прогнати механіку самому:

```bash
uv run tools/verify_raw.py                 # цілісність фікстур
uv run tools/verify_values.py --all        # значення проти джерел
```

Якщо тут уже є ❌ `НЕМА` — виправ це до запуску агента: немає сенсу витрачати
повну перевірку на документ із явно битими посиланнями.

Якщо на критичні значення немає фікстур — заморозь джерела:

```bash
uv run tools/freeze.py <URL> --source mann-filter --slug <...>
```

Для джерел за Cloudflare (PartSouq, частина магазинів) — Claude in Chrome, інакше попроси оператора зберегти MHTML —
порядок у `raw/README.md`. Скріншот не підходить: із нього не видобувається текст,
тобто механічно звірити неможливо.

## Як запускати

Через `Agent` tool, `subagent_type: "perevirka"`. У промпті дати:

1. **Який документ перевіряти** — конкретний шлях
2. **Контекст машини**, якщо перевіряється гайд під конкретне авто: модель, кузов,
   код двигуна, kW, роки, VIN
3. **На що звернути увагу**, якщо є підозри

Чого **не** давати в промпті: своїх висновків про те, що правильно. Фраза
«перевір, але там усе вірно, я звіряв» знищує сенс запуску. Агент мусить дійти
до висновку сам, із джерел.

Приклад промпту:

```
Перевір guides/bmw-n47-to-filtry.md.

Авто, під яке писався гайд: BMW 520d Touring (F11), 2012, двигун N47D20C
135 kW / 184 к.с., VIN <17 символів>.

Документ піде в роботу на реальній машині й у замовлення деталей.
```

## Після звіту

Агент пише в `_ai/perevirka_log.md` і повертає вердикт із проблемами за серйозністю.
Далі твоя робота:

1. **🔴 і 🟠 виправити одразу** — це невірні артикули й моменти затяжки,
   тобто гроші й зіпсовані деталі
2. **⚠️ БЕЗ ДЖЕРЕЛА** — або знайти джерело й додати посилання, або знизити
   позначку довіри твердження до 🟡 чи 🔴
3. **🔒 НЕДОСТУПНО** — лишити як є, але в документі має бути видно, що значення
   не підтверджене. Недоступне джерело — це не підтвердження
4. Показати оператору підсумок і закомітити правки

Якщо агент знайшов помилку, яку я ж і зробив — записати її в `_ai/lessons.md`,
у розділ про власні помилки. Ці повторюються найчастіше.

## Коли запускати без запиту оператора

Сам пропонуй перевірку, коли:

- гайд дописаний і має піти в роботу на машині
- складено кошик закупки на суму, яку неприємно викинути
- у документі з'явилися моменти затяжки
- документ переписувався кілька разів і втратив слід джерел

Не пропонуй на кожну дрібну правку — перевірка має сенс перед дією, а не замість
роботи.
