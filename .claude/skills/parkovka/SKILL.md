# Паркування

Вбудована пам'ять вимкнена, а оператор працює з двох комп'ютерів. Отже **єдиний
носій контексту між машинами — git**. Непушений хендоф на іншій машині не існує.

Звідси головне: паркування не вважається виконаним, доки `git push` не пройшов.

## Де лежить стан

Стан поділений по машинах:

```
cars/<регномер>/<авто>-stan.md        стан роботи по машині — повний (шаблон templates/stan.md)
_ai/HANDOFF.md                        табло: одна стрічка на машину + справи, що не належать жодній машині
```

Коли оператор називає номер, хук `UserPromptSubmit` (`tools/hooks/car_context.py`) сам вкидає в контекст `-stan.md`
цієї машини. Тому все, що треба знати, щоб продовжити роботу по машині, має лежати в її `-stan.md`, а не в табло.

## Крок 1. Перепиши `-stan.md` кожної машини, якої торкалась сесія

Які машини: змінені файли в `cars/<номер>/` (`git status --short cars/`) плюс ті, про які говорили без змін
у файлах (оператор щось повідомив, рішення по машині). Для кожної — `cars/<номер>/<авто>-stan.md` за
`templates/stan.md`, **перезаписати цілком**. Файлу ще немає — створити. Попередні версії — в історії git, окремий
архів не потрібен.

Пиши так, щоб нова сесія без цього контексту зрозуміла за хвилину. Конкретика замість узагальнень: не «працювали
над ТО», а «артикули звірені, кошик 1 828, запчастини не куплені».

**«Відкриті питання» — найцінніший розділ.** Туди все, що висить без відповіді: чого не перевірили, що треба
підтвердити руками, де зробили припущення. Без цього наступна сесія почне з вигадування відповідей.

Робота по машині закінчена (машина віддана) — статус «готово», а рядок у табло прибрати.

## Крок 1а. Перепиши табло `_ai/HANDOFF.md`

Перезаписується цілком; старий — в архів (крок 3). Структура:

```markdown
# HANDOFF — табло майстерні

**Оновлено:** YYYY-MM-DD

## Машини в роботі

| Машина | Статус | Чекаємо | Стан |
|---|---|---|---|
| AA1234BB Hilux 2008 | підбір готовий, кошик 12 200 грн | оператор купує; к-сть листів ресори | `cars/aa1234bb/toyota-hilux-aa1234bb-stan.md` |

## Останнє

<1–3 рядки: чим займалась ця сесія і що з цього головне.>

## Система

<Скрипти, скіли, kb/, контейнер — те, що не належить жодній машині: що зроблено, що далі, відкриті питання.>

## Стан репо
```

Стрічка машини — коротка, подробиці лише в її `-stan.md`. Машини без змін за сесію лишаються як були.

У «Стан репо» напиши прямо, чи все закомічено, чи щось лишилось у робочій копії, і на якій гілці.

## Крок 2. Допиши журнали, якщо було що

- **`_ai/decisions.md`** — ухвалене рішення + **чому**. Тільки дописувати, старі
  записи не правити. Без «чому» запис марний: через місяць рішення переглядатимуть
  і без обґрунтування скасують
- **`_ai/lessons.md`** — граблі: що не працює, який номер виявився невірним, який
  сайт ріже доступ. Включно зі своїми помилками: саме вони найдорожчі, бо
  повторюються. Є окремий розділ під них

Нічого нового не з'ясували — не вигадуй записи заради заповнення.

## Крок 2а. Знахідки для покращення — запропонувати

Перед паркуванням переглянь сесію й зібери, **що варто змінити в самій системі** — скілах, `CLAUDE.md`,
шаблонах, скриптах, `kb/`:

- що оператор просив **удруге** або виправляв за мною
- де інструмент заважав (формат файлу, якого скрипт не бере; хибні спрацювання перевірок)
- які сайти / джерела знайшлися і чи вони вже в матриці `kb/`
- які мої помилки повторюються (→ `_ai/lessons.md`)

Покажи оператору коротким списком: що і куди внести — і **чекай відповіді до коміту**. Порядок: знахідки →
відповідь оператора → внести погоджене → тоді крок 3–4 (архів, коміт, пуш) одним комітом паркування. Не комітити
паркування раніше, ніж оператор відповів на знахідки: інакше погоджені правки йдуть другим комітом, а хендоф уже
каже «все закомічено» (оператор, 2026-10-24). Відхилене — не наполягати. Якщо знахідок немає — так і скажи, не
вигадуй, і йди далі без очікування.

## Крок 3. Архівуй попередній хендоф

Перед перезаписом табло збережи старе (`-stan.md` машин не архівуються — їх історія в git):

```bash
cp _ai/HANDOFF.md _ai/archive/$(date +%F)-<короткий-слаг>.md
```

Архів потрібен, щоб можна було відмотати: «а що ми думали два тижні тому».

## Крок 4. Коміт і пуш — обов'язково

```bash
uv run tools/guides_to_cars.py      # копії гайдів у папках машин — свіжі
git add -A && git status --short
git commit -m "Паркування: <одним рядком що саме припарковано>"
git pull --rebase                    # поки йшла сесія, інший комп міг запушити своє
git push
```

`git pull --rebase` — обов'язково перед пушем: хук тягне зміни лише на старті сесії, а довга сесія на одному компі
може перетнутися з роботою на іншому. Конфлікт найчастіше в `_ai/HANDOFF.md` (обидві сесії його переписують):
взяти табло іншого компа за основу й дописати свої стрічки (у `-stan.md` конфлікт можливий, лише якщо обидва компи
працювали з тією самою машиною — тоді так само), потім `git add` → `git rebase --continue` → перезапустити
`guides_to_cars.py --check` і `verify_values.py --all` (злиті зміни могли їх зачепити) → `git push`.

Перевір вивід пушу. Якщо пуш не пройшов — скажи оператору прямо, що стан
**не доїде на іншу машину**, і що робити (конфлікт, немає мережі, не та гілка).
Не завершуй паркування з непушеним комітом і не кажи, що все збережено.

Якщо в робочій копії лишилась незавершена робота, яку комітити не варто —
опиши це в «Стан репо», щоб на іншій машині не шукали загублене.

## Крок 5. Скажи оператору

Коротко: що припарковано, що далі, і що на іншому комп'ютері **почати з `git pull`**.

## Початок сесії на іншій машині

Зазвичай робити нічого не треба: хук `SessionStart` (`.claude/settings.json` →
`tools/hooks/session_start.py`) сам робить `git fetch` + `merge` і вкидає табло в контекст, а хук `UserPromptSubmit`
(`tools/hooks/car_context.py`) — `-stan.md` машини, щойно оператор назве її номер.

Але хук **не робить pull**, якщо в робочій копії є незакомічені зміни — щоб не
влізти в конфлікт посеред незавершеної роботи. У такому разі він про це пише,
і розібратися треба вручну: подивитись, що там висить, і вирішити — докомітити,
відкласти чи скинути.

Якщо хендофа на старті сесії не було взагалі (хук не спрацював, не той каталог):

```bash
git pull && cat _ai/HANDOFF.md
```

Pull першим, бо інакше є ризик наробити паралельних змін і зустріти конфлікт
саме в момент паркування, коли вже нема часу розбиратись.
