# Гайд ремонту

Гайд читає механік біля машини, з телефона, з брудними руками. Хибний момент — зірвана різьба, пропущений крок —
розібрана машина, якій бракує деталі. Тому гайд пишеться **за офіційним мануалом саме під нашу версію мотора**,
кожне число зводиться до джерела, а людина отримує зручний HTML із малюнками.

Форма — `templates/guide.md` (прочитай перед роботою). Назва — `guides/<марка>-<мотор>-<опис>.md`.

## 0. Спершу — чи гайд уже є

Шукати в `guides/README.md` за кодом мотора (родиною) і кузова/платформи машини. Є гайд на ту саму родину — **не
писати новий**, а додати розділ під нашу машину (доступ, варіант, свій ремінь тощо) і рядок машини в індексі.
Назва нового гайда — за правилом у `CLAUDE.md`.

## 1. Визначити, під що пишемо

З файлу машини й EPC по VIN: код мотора, **версія** (потужність, Euro-клас, «High Power» тощо), КПП, роки.
Версія важлива: у L200 4D56 версії 136 і 178 к.с. мають різні моменти насоса ГПК, інший навісний.

## 2. Знайти мануал — у такому порядку

1. **Офіційний онлайн** — спершу. Для Mitsubishi (і моторів PSA у Mitsubishi) — mmc-manuals.ru, каталог моделі
   на сторінці «Руководства по ремонту», див. `kb/dzherela-artykuliv-ta-danych.md`. Онлайн-сторінка дає людині
   клікабельне посилання
2. **Своя бібліотека мануалів** — `kb/manualy.md` (поза репо: шлях і що там є)
3. Мануал іншої марки з тим самим мотором — матриця в `kb/`

**Перевірити, що мануал про нашу версію:** розділ General information / Major specifications — чи є колонка
нашої версії. Новіша редакція часто покриває те, чого нема в старій (L200: диск 2007 — лише 136 к.с.,
онлайн-редакція 2015 — з High Power). Брати кроки з гілки нашої версії («<High power…>», а не «<Except…>»).

## 3. Заморозити джерела

workshop-manuals.com — скриптом: `uv run tools/workshop_manuals.py index <марка>/<модель> --grep <слово> --grep <мотор>`
знаходить розділ, `read <URL> --freeze --slug <марка>-<мотор>-<розділ>` друкує текст і заморожує сторінку разом з
кожним малюнком окремим файлом. Решта — `freeze.py`:

```bash
uv run tools/freeze.py <URL сторінки> --source workshop-manuals --slug <марка>-<мотор>-<розділ>   # MHTML + картинки
uv run tools/freeze.py <URL малюнка .png> --source workshop-manuals --slug <...>-img-<код>        # окремий малюнок
uv run tools/freeze.py <файл з бібліотеки> --source workshop-manuals --slug <...> --url "books:<шлях>"
uv run tools/freeze.py <URL .pdf> --page N --source workshop-manuals --slug <...>-img-<сторінка>   # сторінка PDF → PNG для HTML
```

- **Моменти й мітки часто тільки на малюнках.** Подивитись кожен малюнок розділу (Read на PNG), моменти з малюнків
  переписати в ручну розшифровку `<...>.transcript.txt` (шапка «РУЧНА РОЗШИФРОВКА…, звіряти з PNG») і заморозити її —
  на неї посилаються значення з малюнків
- **Кожне «Refer to …»** у кроках, які реально робимо (Pre-removal, підготовка), — відкрити й заморозити теж.
  Там ховаються додаткові вузли, моменти й «N»-деталі
- **Позначка «N»** на малюнку — деталь тільки нова: прокладки, O-ring. Усе це — у закупку й у таблицю одноразових
- **Сайт ріже скрипти (403, Cloudflare) або форум закритий** — спершу Claude in Chrome (`CLAUDE.md`, «Браузер
  оператора»): `get_page_text` → файл → `freeze.py --url`. Малюнки так не дістати — їх `freeze.py` по URL картинки
- **Сайт мануалу тупить** (хвилина на сторінку, 522/524) — не чекати годинами чергу, а **одразу дати оператору список
  посилань** «зберегти як MHTML» у `downloads/`; далі `freeze.py <файл> --url <URL сторінки>` (URL — з заголовка
  `Snapshot-Content-Location` у MHTML). **Малюнки з MHTML заморожувати окремими файлами** з `--url` картинки:
  `md2html.py` шукає малюнок за URL у `MANIFEST.tsv` і всередину MHTML не дивиться. Повільний сайт — `freeze.py --timeout`
- **Момент — лише з джерела про нашу деталь.** Перш ніж брати момент з інструкції (навіть «під нашу модель»), звірити
  кріплення: розмір головок / різьба болта в джерелі проти нашої деталі (отвір сайлентблока, різьба з картки болта,
  OE-група). Не сходиться — це інша конструкція, моменти з неї не брати; шукати інструкцію під **ту саму OE-групу** на
  іншій моделі (у неї той самий вузол) і позначати 🟡 з назвою моделі
- **Мануал сусідньої моделі** (Octavia II для Superb II) — значення з нього позначати 🟡 для нашої машини, і
  **кількість однотипних деталей** (болти подушки, ролики) рахувати по EPC **нашої** моделі, а не з малюнка сусідньої

## 3а. Знайти відео

Ремонтуємо в полі — відео до кроку там часто корисніше за текст. Гайд без відео не здавати.

```bash
uv run tools/youtube.py search "<мотор> timing belt" "<модель> <рік> <робота>" "<запит мовою ринку>"   # WebSearch YouTube не бачить
uv run tools/youtube.py info <id> …          # опис, дата, **розділи з таймкодами**
uv run tools/youtube.py frames <id> … -o <scratchpad>/a.jpg   # ≤4 відео на аркуш, відкрити через Read
uv run tools/youtube.py transcript <id> … -o <scratchpad>/tr   # що кажуть і на якій хвилині; немає субтитрів — лише кадри
```

- **Відсіяти чуже покоління.** У тієї самої серії мотора бувають різні приводи (4D56 з ТНВД і 4D56U common rail).
  За кадрами видно, той це мотор чи ні, у машині чи на стенді. Брати насамперед відео **в машині того ж кузова**
  (поле: доступ і є головна проблема), на стенді — лише для того, що там краще видно
- Шукати кількома мовами: іспанською, німецькою, малайською/індонезійською для азійських пікапів —
  там часто найповніші відео
- **Транскрипт — замість «не переглянуто».** `transcript` дає текст ролика блоками по ~20 с з таймкодами: прочитати,
  чи це наш мотор і наш порядок робіт, знайти момент для кроку, виписати в «Підводні камені», де відео розходиться з
  мануалом або показує те, чого в мануалі немає (доступ на нашому кузові). Числа з транскрипту не брати — автоматичні
  субтитри плутають цифри. Транскрипт — у scratchpad, у `raw/` не
  класти (це не джерело значень). У таблиці «Відео» позначати, чи транскрипт прочитано
- **Код мотора у відео — шукати першим ділом у перших блоках транскрипту** («Motorkennbuchstabe …», «engine code …»):
  назва ролика («Superb 3T») про покоління мотора не каже. Інший мотор — підписати в таблиці «лише доступ на кузові»,
  моменти й деталі з нього не брати
- **Таймкоди** — з розділів (`info`) або з транскрипту. Посилання `…watch?v=<id>&t=<с>s` у кроці стає компактною кнопкою «▶» у HTML;
  без розділів — `&t=0s` для короткого відео на один вузол
- Прев'ю для карток у HTML заморозити: `uv run tools/freeze.py https://img.youtube.com/vi/<id>/hqdefault.jpg --source youtube --slug <id>`.
  Саме відео не завантажувати (`_ai/decisions.md`)
- Позначка 🟡 «відібрані, не переглянуті» і рядок у «Джерелах». Моменти з відео — не беремо; бачиш у відео інше, ніж
  у мануалі, — записати в «Підводні камені» як питання

## 4. Писати

- **Паспорт роботи й «Інструменти» — на самому початку**, одразу під «Застосовно до», перед відео й процедурою:
  механік має знати, чи братися, скільки це часу і що замовити заздалегідь, **до** того, як почне читати кроки.
  Складність — за шкалою з шаблону (критерії, не відчуття); час — скілом `robotohodyny`, не з пам'яті (не оцінено —
  так і написати). Інструмент — трьома рівнями 🔴 / 🟠 / ⚪: 🔴 спецінструмент (номер виробника, аналог, де взяти)
  **іде ще й у список закупки машини** — без нього робота стане на півдорозі, як без одноразового болта. Спецінструмент
  шукати в самому мануалі: позначки T10…, V.A.G …, 0188-…, MD99…, 09xxx-… у кроках і в списку «Special tools»
- Шаблон `templates/guide.md`: паспорт, інструменти, відео, порядок робіт, таблиця моментів, **зведена таблиця затяжок у кінці**, одноразові болти,
  джерела з рівнем довіри
- **Посилання для людини й фікстура для скрипта — разом.** Розділ мануалу — клікабельне посилання на онлайн-сторінку
  `[11A Timing belt](https://…)`; значення — у бектиках, у тому ж рядку шлях `raw/…` (його `verify_values.py` звіряє,
  а в HTML для телефона він ховається)
- **Малюнок — посиланням на файл картинки:** `[малюнок AC502914](https://…/AC502914AB00ENG.png)`. Якщо картинка
  заморожена (URL є в `raw/MANIFEST.tsv`), `md2html.py` вбудує її в HTML прямо в крок
- **Відео — обов'язково** (див. розділ 3а): таблиця в розділі «Відео» і посилання з таймкодом у кроках
- **Кожен малюнок, на який посилається крок, — відкрити (Read) і звірити з текстом кроку.** Не ставити посилання за
  порядком малюнків на сторінці: сусідній малюнок часто про інший варіант або інший вузол
- **Відео дає інший момент, ніж мануал** — рядок у «Підводні камені»: що в відео, що в мануалі, що беремо (мануал)
- **Стан нової деталі при встановленні** (натягувач зафіксований / гайка на 2–4 Нм / ексцентрик до упору) — якщо мануал
  його задає в «Conditions» перед встановленням, писати в кроці, де деталь ставиться
- Розбіжності між версіями мотора — прямо в тексті: що з якої гілки мануалу і що звіряти на машині
- Важливе не ховати **тільки** в шляху `raw/…` — у HTML для людини шляхи прибираються

## 5. Перевірити й видати

```bash
uv run tools/verify_values.py <гайд>        # 0 НЕМА
uv run tools/guides_to_cars.py              # копія в cars/<номер>/guides/ + .html для телефона
uv run tools/guides_to_cars.py --check
```

Гайд має бути посиланням у файлі машини (`guides/<файл>.md`), інакше копія й HTML не згенеруються.

Далі — скіл `perevirka` (окремий агент) перед тим, як гайд піде в роботу. Після правок — знову `guides_to_cars.py`.

**HTML для телефона:** `cars/<номер>/guides/<гайд>.html` — один файл, малюнки всередині, працює без інтернету.
Оператор перекидає його на телефон сам. Правити тільки `.md`
в `guides/` — HTML і копія перегенеровуються. Запускати через `uv run` (пакет `markdown` — з `pyproject.toml`); без нього скрипт HTML не робить, лише
пише «⚠ немає markdown» — перевіряти, що `.html` поруч з копією оновився.

## Самонавчання

Якщо по ходу видно, що процес можна покращити — запропонувати оператору конкретну правку цього скіла, шаблону чи
скрипта одним рядком. Висновки про конкретні деталі чи значення сюди не вносити — тільки правила роботи.
