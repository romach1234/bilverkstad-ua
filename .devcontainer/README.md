# Контейнер для Linux

Усі інструменти `tools/` в одному образі: `uv` (Python і бібліотеки з `pyproject.toml`), poppler, `gh`, deno, Claude
Code. На кожному комп'ютері однакові — щоб не було «на одному є `markdown`, на іншому ні».

На Windows контейнер не потрібен — там `install.ps1` (`README.md`).

| Файл | Що |
|---|---|
| `Dockerfile` | Образ. Часовий пояс — `ARG TZ` |
| `devcontainer.json` | Конфіг: монтування, перший запуск |

Відкрити: VS Code → `Dev Containers: Reopen in Container`. Перший запуск сам поставить бібліотеки й запустить
перевірку середовища й джерел (`uv run tools/perevirka_seredovyshcha.py`).

Потрібно на хості: Docker, VS Code з розширенням Dev Containers, теки `~/.claude` і файл `~/.claude.json` (з'являються
після першого входу в Claude Code на хості), `~/.ssh` з ключем для GitHub.

## Чому монтування саме такі

Claude Code у контейнері й поза ним має бачити **ті самі чати**:

- **Репо — за тим самим абсолютним шляхом, що на хості** (`workspaceMount` = `${localWorkspaceFolder}`). Claude Code
  кладе чати в `~/.claude/projects/<шлях-репо>/`; зі звичним `/workspaces/...` це була б інша папка й інші чати
- **`~/.claude` і `~/.claude.json` хоста** — чати, налаштування, вхід в акаунт
- **Користувач з тим самим ім'ям і UID**, що на хості (`$USER`, UID 1000 — інший UID поправити в `devcontainer.json`):
  шляхи `/home/<user>/…` збігаються, права на файли не ламаються
- **`~/.ssh` тільки для читання** — `git pull/push` (хук старту сесії і `parkovka`)
- **Бібліотека мануалів** — за потреби, рядок у `mounts` (`kb/manualy.md`)

Чати між **комп'ютерами** так не синхронізуються — лише між хостом і контейнером одного комп'ютера. Між
комп'ютерами — git (`_ai/HANDOFF.md`).

## Обмеження

- **Claude in Chrome** з контейнера на Linux працює (розширення в Chrome хоста); **з WSL — ні**
- Образ без GUI: HTML гайдів відкривати з хоста
